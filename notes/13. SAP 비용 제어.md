# SAP 비용 제어

# 큰 그림

섹션 13은 비용을 직접 줄이는 서비스와, 비용이 커지는 원인을 찾아내는 서비스를 구분하는 게 핵심이다.

```text
누가 비용을 만들었는지 분류
→ Cost Allocation Tags

태그 누락 리소스 찾기/일괄 수정
→ Tag Editor

모범 사례와 비용 최적화 권고
→ Trusted Advisor

서비스 한도 확인/증가 요청
→ Service Quotas

사용량 기반 비용 분석
→ Cost Explorer

예산과 알림
→ AWS Budgets

리소스 right-sizing 권고
→ Compute Optimizer

EC2 장기 약정 할인
→ Reserved Instances / Savings Plans
```

# 비용 할당 태그

Cost Allocation Tag는 비용을 프로젝트, 팀, 환경, 서비스별로 나누어 추적하기 위한 태그다.

```text
Project=sap-study
Team=platform
Environment=prod
CostCenter=1234
```

시험 감각:

```text
팀별/프로젝트별 비용을 보고 싶다
부서별 chargeback/showback이 필요하다
비용 보고서에서 태그 기준으로 필터링하고 싶다
→ Cost Allocation Tags
```

주의할 점:

- 태그는 리소스에 붙이는 이름표다.
- 비용 리포트에 쓰려면 cost allocation tag로 활성화해야 한다.
- 태그가 없는 리소스는 비용 분류에서 빠지거나 `untagged`로 남는다.

# Tag Editor

Tag Editor는 여러 리전/여러 리소스에 걸쳐 태그를 검색하고 수정하는 도구다.

시험 감각:

```text
태그가 빠진 리소스를 찾아야 한다
여러 리소스에 태그를 한 번에 붙이고 싶다
→ AWS Tag Editor
```

# Trusted Advisor

Trusted Advisor는 AWS 계정의 모범 사례 체크 도구다.
비용 최적화뿐 아니라 보안, 성능, 내결함성, 서비스 한도도 본다.

시험에서 비용 제어로 자주 나오는 감각:

```text
사용하지 않는 리소스
낮은 사용률의 EC2
유휴 Load Balancer
비효율적인 Reserved Instance 사용
→ Trusted Advisor 비용 최적화 체크
```

Trusted Advisor는 "분석해서 권고"하는 도구다.
직접 자동으로 비용을 줄이는 실행 도구라기보다, 무엇을 고치면 좋을지 알려준다.

# Service Quotas

Service Quotas는 AWS 서비스 한도를 조회하고 증가 요청하는 서비스다.

비용 제어 섹션에 있지만 핵심은 비용보다 "한도 관리"다.

```text
현재 계정의 서비스 한도 확인
한도 증가 요청
CloudWatch alarm으로 quota 사용률 감시
→ AWS Service Quotas
```

# EC2 구매 옵션과 Savings Plans

EC2 비용 문제는 워크로드 성격을 보고 구매 옵션을 고르는 문제로 나온다.

| 옵션 | 맞는 상황 |
| --- | --- |
| On-Demand | 예측 불가, 약정 없음, 가장 유연 |
| Reserved Instances | 특정 인스턴스 패밀리/리전/AZ를 장기간 안정적으로 사용 |
| Savings Plans | 시간당 사용 금액을 약정하고 더 유연하게 할인 |
| Spot | 중단 가능 워크로드, 가장 저렴 |
| Dedicated Hosts | 라이선스/규정/물리 서버 단위 요구 |

시험 감각:

```text
항상 켜져 있는 안정적 워크로드
→ RI 또는 Savings Plans

인스턴스 패밀리/리전/OS 변화 가능성이 있다
→ Savings Plans가 더 유연

중단되어도 재시도 가능한 배치/HPC
→ Spot

기존 소프트웨어 라이선스가 물리 서버 단위
→ Dedicated Host
```

# S3 비용 절약

S3 비용 절약은 스토리지 클래스와 Lifecycle Rule을 연결해서 생각한다.

```text
자주 접근
→ S3 Standard

자주 접근하지 않지만 즉시 접근 필요
→ Standard-IA / One Zone-IA

접근 패턴을 모름
→ Intelligent-Tiering

아카이브
→ Glacier Instant Retrieval / Flexible Retrieval / Deep Archive
```

시험 감각:

```text
객체가 오래되면 자동으로 저렴한 클래스로 이동
→ S3 Lifecycle Policy

접근 패턴을 예측하기 어렵다
→ S3 Intelligent-Tiering

삭제 비용/검색 비용/최소 보관 기간까지 고려
→ IA/Glacier 계열 선택 문제
```

S3 Analytics는 객체 접근 패턴을 분석해서 Standard에서 Standard-IA로 옮기는 게 적절한지 판단하는 데 도움을 준다.

# AWS Budgets와 Cost Explorer

Cost Explorer는 과거 비용과 사용량을 분석하는 도구다.
Budgets는 예산을 정하고 초과/예상 초과 시 알림을 받는 도구다.

```text
과거 비용 분석, 그래프, 서비스별 비용 추세
→ Cost Explorer

월 비용이 80% 넘으면 알림
RI/SP 사용률 또는 커버리지 예산
→ AWS Budgets
```

시험 감각:

```text
지난 6개월간 비용 추세를 분석하고 싶다
→ Cost Explorer

비용이 특정 금액을 넘기 전에 알림 받고 싶다
→ AWS Budgets
```

# Compute Optimizer

Compute Optimizer는 실제 사용률 지표를 기반으로 리소스 크기 조정을 추천한다.

추천 대상 예:

```text
EC2 instance type
Auto Scaling Group
EBS volume
Lambda memory
ECS service on Fargate
```

시험 감각:

```text
CPU/메모리 사용률을 보고 인스턴스 크기를 줄이거나 키우는 추천
리소스 right-sizing
과대 프로비저닝 비용 절감
→ AWS Compute Optimizer
```

# EC2 Reserved Instance

Reserved Instance는 장기간 사용할 EC2 용량에 대해 할인받는 방식이다.

중요한 비교:

```text
Standard RI
→ 할인 큼, 변경 유연성 낮음

Convertible RI
→ 할인은 조금 낮지만 인스턴스 패밀리 등 변경 가능

Zonal RI
→ 특정 AZ 용량 예약 효과

Regional RI
→ AZ 유연성, capacity reservation 효과는 약함
```

시험 감각:

```text
특정 AZ에 용량을 보장하고 싶다
→ Zonal RI 또는 Capacity Reservation

장기 비용을 줄이고 싶지만 인스턴스 타입 변경 가능성 있음
→ Convertible RI 또는 Savings Plans
```

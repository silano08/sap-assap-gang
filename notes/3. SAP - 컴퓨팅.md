# SAP 컴퓨팅

# HPC, 고성능 컴퓨팅

HPC는 High Performance Computing이다.

쉽게 말하면:

```text
엄청 많은 계산을
짧은 시간 안에
많은 컴퓨팅 리소스로 병렬 처리하는 것
```

AWS에서 HPC가 잘 맞는 이유:

- 필요할 때 대량의 EC2 인스턴스를 빠르게 띄울 수 있다.
- 작업 속도를 높이고 싶으면 리소스를 더 붙이면 된다.
- 사용한 만큼만 비용을 낸다.
- 작업이 끝나면 인프라를 삭제해서 비용을 멈출 수 있다.

시험용 한 줄:

```text
HPC on AWS = 대량 데이터 + 고성능 컴퓨팅 + 빠른 네트워크 + 고성능 스토리지 + 자동화 조합
```

## HPC 사용 사례

- 유전학 분석
- 컴퓨터 화학
- 재무 위험 모델링
- 일기 예보
- 머신 러닝 / 딥 러닝
- 자율주행 시뮬레이션

핵심 감각:

```text
계산량이 크고,
병렬 처리가 가능하고,
짧은 시간에 결과가 필요한 작업
```

## 데이터 이동

HPC는 계산 전에 대량 데이터를 AWS로 옮기는 일이 중요하다.

### Direct Connect

- 온프레미스와 AWS를 전용 네트워크로 연결한다.
- 인터넷을 통하지 않는 private connection이다.
- GBps급 대역폭으로 안정적으로 대량 데이터를 전송할 수 있다.

시험 감각:

```text
온프레미스와 AWS 사이를 지속적으로 고속 연결
→ Direct Connect
```

### Snowball / Snowmobile

- 물리 장비로 데이터를 옮긴다.
- 네트워크로 전송하기 어려운 페타바이트급 데이터에 적합하다.
- 한 번에 대량 데이터를 AWS로 옮길 때 사용한다.

시험 감각:

```text
네트워크로 옮기기엔 너무 큰 데이터
→ Snowball / Snowmobile
```

### DataSync

- 온프레미스 스토리지와 AWS 스토리지 간 데이터 전송 서비스다.
- DataSync agent를 설치해서 사용한다.
- NFS / SMB 같은 온프레미스 파일 시스템에서 S3, EFS, FSx로 전송할 수 있다.

시험 감각:

```text
온프레미스 NFS/SMB → AWS S3/EFS/FSx 반복 전송
→ DataSync
```

## 컴퓨팅과 네트워킹

### EC2 인스턴스

HPC의 기본 컴퓨팅 리소스는 EC2다.

- CPU 최적화 인스턴스:
  - 일반 계산, 시뮬레이션, 수치 연산에 적합.
- GPU 최적화 인스턴스:
  - 머신 러닝, 딥 러닝, 그래픽/병렬 연산에 적합.

비용 최적화:

- Spot Instance / Spot Fleet:
  - 중단 가능하거나 재시도 가능한 HPC 작업 비용을 크게 줄일 수 있다.
- Auto Scaling:
  - 계산량에 따라 EC2 플릿을 늘리거나 줄인다.

### Cluster Placement Group

분산 계산에서 EC2 인스턴스끼리 빠르게 통신해야 하면 클러스터 배치 그룹을 쓴다.

- 동일 AZ 안에 인스턴스를 가깝게 배치한다.
- 낮은 지연 시간과 높은 네트워크 성능을 얻는다.
- HPC처럼 노드 간 통신이 많은 워크로드에 적합하다.

시험 감각:

```text
EC2끼리 아주 빠르게 통신해야 함
→ Cluster Placement Group
```

주의:

```text
Cluster Placement Group = 고성능 네트워크 배치 전략
Multi-AZ 고가용성 전략이 아님
```

## EC2 향상된 네트워킹

EC2 향상된 네트워킹은 SR-IOV 기반으로 더 높은 대역폭, 높은 PPS, 낮은 지연 시간을 제공한다.

```text
SR-IOV = 가상화 오버헤드를 줄여 네트워크 성능을 높이는 기술
```

### ENA, Elastic Network Adapter

- 최신 EC2 향상된 네트워킹 방식이다.
- 최대 100Gbps급 네트워킹을 지원한다.
- 높은 대역폭, 높은 PPS, 낮은 지연 시간이 핵심이다.

시험 감각:

```text
EC2 enhanced networking
→ ENA
```

### Intel 82599 VF

- 예전 방식의 향상된 네트워킹 옵션이다.
- 최대 10Gbps 수준.
- ENA보다 레거시 옵션으로 보면 된다.

시험에서는 이름이 나오면:

```text
Intel 82599 VF = 구형 enhanced networking
ENA = 최신 enhanced networking
```

### EFA, Elastic Fabric Adapter

EFA는 HPC 전용에 가까운 고성능 네트워크 어댑터다.

- ENA보다 HPC에 더 특화된 옵션이다.
- Linux에서만 사용한다.
- 노드 간 통신이 많은 tightly coupled workload에 적합하다.
- MPI(Message Passing Interface)를 사용하는 분산 계산에 적합하다.
- OS를 우회하는 방식으로 더 낮은 지연 시간과 안정적인 전송을 제공한다.

시험 감각:

```text
HPC + Linux + MPI + 노드 간 초저지연 통신
→ EFA
```

ENA / EFA / ENI 차이:

```text
ENI = EC2에 붙는 가상 네트워크 인터페이스
ENA = EC2 enhanced networking용 어댑터
EFA = HPC/MPI용 초저지연 네트워크 어댑터
```

## 스토리지

HPC는 계산 성능만큼 스토리지 성능도 중요하다.

### EBS

- EC2에 붙는 블록 스토리지다.
- `io2 Block Express`를 사용하면 매우 높은 IOPS를 제공한다.
- 강한 내구성과 일관된 성능이 필요할 때 사용한다.

시험 감각:

```text
고성능 블록 스토리지
→ EBS io2 Block Express
```

### Instance Store

- EC2 호스트에 직접 붙은 로컬 스토리지다.
- 매우 낮은 지연 시간과 높은 IOPS를 제공한다.
- 수백만 IOPS 수준까지 가능하다.
- 단, 인스턴스가 종료/손실되면 데이터도 사라질 수 있다.

시험 감각:

```text
가장 빠른 임시 로컬 스토리지
→ Instance Store

영구 저장 필요
→ EBS/S3/EFS/FSx 고려
```

### S3

- 대량 객체 저장소다.
- 파일 시스템이 아니라 object storage다.
- HPC 입력/출력 데이터, 원본 데이터, 결과물 저장에 자주 사용한다.

### EFS

- 여러 EC2에서 공유할 수 있는 Linux 파일 시스템이다.
- 파일 시스템 전체 규모에 따라 성능이 확장된다.
- Provisioned Throughput / Provisioned IOPS 계열 옵션으로 성능을 높일 수 있다.

### FSx for Lustre

HPC에서 가장 시험 포인트가 되는 파일 시스템이다.

- Lustre는 Linux와 HPC 클러스터에 많이 쓰이는 고성능 파일 시스템이다.
- 수백만 IOPS를 제공할 수 있다.
- S3와 연동해서 대량 데이터를 고성능 파일 시스템처럼 처리할 수 있다.

시험 감각:

```text
HPC 전용 고성능 파일 시스템
→ FSx for Lustre
```

S3와 FSx for Lustre 감각:

```text
S3 = 대량 데이터 저장소
FSx for Lustre = 계산 중 빠르게 읽고 쓰는 고성능 파일 시스템
```

## 자동화와 오케스트레이션

### AWS Batch

- 대량 배치 작업을 실행하고 스케줄링하는 서비스다.
- EC2 인스턴스 생성과 작업 실행을 AWS Batch가 관리한다.
- 다중 노드 병렬 작업을 실행할 수 있다.
- HPC 작업을 비교적 쉽게 실행할 때 적합하다.

시험 감각:

```text
대량 계산 작업을 큐에 넣고 EC2에서 자동 실행
→ AWS Batch
```

### AWS ParallelCluster

- AWS에서 HPC 클러스터를 배포하기 위한 오픈 소스 클러스터 관리 도구다.
- 텍스트 설정 파일로 클러스터를 정의한다.
- VPC, 서브넷, 인스턴스 유형, 클러스터 구성을 자동화할 수 있다.
- HPC 클러스터를 직접 구성해야 하는 경우에 적합하다.

시험 감각:

```text
AWS에 HPC 클러스터를 구성/관리하는 도구
→ AWS ParallelCluster
```

Batch와 ParallelCluster 차이:

```text
AWS Batch
= 작업 큐/스케줄링 중심
= 배치 작업을 AWS가 관리해서 실행

AWS ParallelCluster
= HPC 클러스터 구성 도구
= 클러스터 자체를 만들고 운영하는 느낌
```

## 시험용 한 번에 정리

```text
대량 데이터 전송
→ Direct Connect / Snowball / DataSync

고성능 계산
→ CPU/GPU EC2, Spot Fleet, Auto Scaling

노드 간 빠른 통신
→ Cluster Placement Group

EC2 네트워크 성능 향상
→ ENA

HPC/MPI 초저지연 네트워크
→ EFA

고성능 로컬 임시 스토리지
→ Instance Store

고성능 블록 스토리지
→ EBS io2 Block Express

HPC 파일 시스템
→ FSx for Lustre

작업 큐 기반 실행
→ AWS Batch

HPC 클러스터 구성
→ AWS ParallelCluster
```

## 헷갈리기 쉬운 포인트

- HPC는 단일 AWS 서비스가 아니다.
  - 여러 서비스 조합으로 계산 성능을 극대화하는 아키텍처다.

- Cluster Placement Group은 고가용성보다 성능이 목적이다.
  - 같은 AZ에 가깝게 배치해서 지연 시간을 줄인다.

- ENA와 EFA를 구분해야 한다.
  - ENA = 일반 EC2 향상된 네트워킹.
  - EFA = HPC/MPI용 초저지연 네트워킹.

- Instance Store는 빠르지만 휘발성이다.
  - 인스턴스 장애/종료 시 데이터 손실 가능.

- FSx for Lustre는 HPC 파일 시스템으로 기억한다.
  - S3와 연동 가능하고 대량 파일 처리에 강하다.

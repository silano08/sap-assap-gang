# SAP 모니터링

# 큰 그림

모니터링 섹션은 "무엇을 관찰하고, 어떤 이벤트에 반응할 것인가"를 구분하는 게 핵심이다.

```text
Metric / Alarm / Dashboard
→ CloudWatch

로그 수집/검색/필터/보존
→ CloudWatch Logs

이벤트 기반 라우팅/자동화
→ EventBridge

분산 추적, 병목 분석
→ X-Ray

AWS 서비스 장애/계정 영향 확인
→ AWS Health Dashboard / Personal Health Dashboard
```

# CloudWatch

CloudWatch는 AWS 리소스와 애플리케이션의 metric을 수집하고 alarm을 만드는 서비스다.

시험 감각:

```text
CPU, 네트워크, 디스크, Lambda 오류율 같은 지표를 감시
임계값 초과 시 알림 또는 Auto Scaling 동작
대시보드로 운영 상태 시각화
→ CloudWatch
```

중요 포인트:

- 기본 metric은 AWS 서비스가 자동으로 보낸다.
- 애플리케이션 고유 지표는 custom metric으로 보낸다.
- EC2 메모리 사용률, 디스크 사용률 같은 OS 내부 지표는 기본 제공이 아니므로 CloudWatch Agent가 필요하다.
- Standard resolution은 보통 1분 단위, high-resolution custom metric은 1초 단위까지 가능하다.

```text
EC2 CPUUtilization
→ 기본 CloudWatch metric

EC2 memory / disk used
→ CloudWatch Agent 필요

애플리케이션 주문 수, 큐 처리 시간
→ Custom Metric
```

# CloudWatch Alarm

Alarm은 metric이 특정 조건을 만족할 때 상태를 바꾼다.

```text
OK
ALARM
INSUFFICIENT_DATA
```

Alarm action으로 할 수 있는 것:

```text
SNS 알림
Auto Scaling action
EC2 action
Systems Manager action
```

시험 감각:

```text
CPU가 70%를 넘으면 ASG scale out
Lambda 오류율이 증가하면 SNS 알림
RDS 지표가 나쁘면 EventBridge/Lambda로 자동화
→ CloudWatch Alarm
```

단, CloudWatch Alarm이 모든 조치를 직접 수행하는 것은 아니다.
복잡한 작업은 SNS/EventBridge/Lambda/SSM과 연결해서 자동화한다.

# CloudWatch Logs

CloudWatch Logs는 로그를 모으고 보존하고 검색하는 서비스다.

기본 구조:

```text
Log Group
→ Log Stream
→ Log Event
```

시험 감각:

```text
EC2 애플리케이션 로그 수집
Lambda 실행 로그 확인
로그 보존 기간 설정
로그에서 특정 패턴을 metric으로 변환
→ CloudWatch Logs
```

중요 포인트:

- Lambda 로그는 CloudWatch Logs로 자동 전송된다.
- EC2/온프레미스 로그는 CloudWatch Agent 설치가 필요하다.
- Retention 설정을 안 하면 로그가 계속 보관되어 비용이 증가할 수 있다.
- Logs Insights로 로그를 쿼리할 수 있다.
- Metric Filter로 로그 패턴을 metric으로 만들 수 있다.

```text
로그 안에 "ERROR"가 몇 번 나왔는지 alarm으로 만들기
→ CloudWatch Logs Metric Filter

로그를 SQL 비슷한 문법으로 검색/분석
→ CloudWatch Logs Insights
```

## Subscription Filter

CloudWatch Logs는 subscription filter를 통해 로그를 다른 서비스로 실시간 전달할 수 있다.

```text
CloudWatch Logs
→ Lambda
→ Kinesis Data Streams
→ Kinesis Data Firehose
→ OpenSearch
```

시험 감각:

```text
로그를 실시간으로 OpenSearch에 넣어 검색/분석
로그 스트림을 Kinesis로 전달
로그 이벤트마다 Lambda 처리
→ CloudWatch Logs Subscription Filter
```

# Amazon EventBridge

EventBridge는 이벤트를 받아 규칙에 맞는 target으로 보내는 이벤트 버스 서비스다.
예전 CloudWatch Events의 확장판이라고 보면 된다.

```text
Event Source
→ Event Bus
→ Rule
→ Target
```

Event source 예:

```text
AWS 서비스 이벤트
Custom application event
SaaS partner event
Scheduled event
```

Target 예:

```text
Lambda
Step Functions
SNS
SQS
Kinesis
ECS task
SSM Automation
```

시험 감각:

```text
EC2 상태 변경 시 Lambda 실행
매일 자정에 배치 작업 실행
SaaS 이벤트를 AWS 워크플로우로 연결
계정 이벤트를 중앙 이벤트 버스로 모으기
→ EventBridge
```

EventBridge는 이벤트 패턴 기반 라우팅이 핵심이다.
단순히 "metric 임계값"이면 CloudWatch Alarm이고, "AWS API/상태 변경 이벤트에 반응"이면 EventBridge를 본다.

추가 포인트:

- EventBridge Archive로 이벤트를 저장할 수 있다.
- Replay로 과거 이벤트를 다시 흘려보낼 수 있다.
- Schema Registry로 이벤트 구조를 관리할 수 있다.
- Cross-account event bus로 여러 계정 이벤트를 중앙 계정에 모을 수 있다.

# X-Ray

X-Ray는 분산 애플리케이션의 요청 흐름을 추적하는 서비스다.
마이크로서비스, Lambda, API Gateway, ECS 같은 구성에서 병목과 오류 지점을 찾을 때 쓴다.

```text
Client request
→ API Gateway
→ Lambda
→ DynamoDB
→ 외부 API
```

이런 흐름에서 어느 구간이 느린지, 어디서 오류가 나는지 trace로 보여준다.

시험 감각:

```text
분산 서비스 간 호출 추적
요청 하나가 여러 서비스로 흘러가는 경로 확인
latency 병목 지점 분석
service map 확인
→ AWS X-Ray
```

핵심 용어:

| 용어 | 의미 |
| --- | --- |
| Trace | 요청 하나의 전체 이동 기록 |
| Segment | 서비스 하나가 처리한 구간 |
| Subsegment | 외부 호출/DB 호출 같은 세부 구간 |
| Annotation | 검색/필터 가능한 key-value |
| Metadata | 추가 데이터, 검색용은 아님 |

CloudWatch가 "지표와 로그"라면, X-Ray는 "요청 경로 추적"이다.

# AWS Health Dashboard

AWS Health Dashboard는 AWS 서비스 상태와 내 계정에 영향 있는 이벤트를 보여준다.

구분:

```text
Service Health Dashboard
→ AWS 서비스의 일반적인 상태

Personal Health Dashboard / AWS Health Dashboard
→ 내 계정과 내 리소스에 영향을 주는 이벤트
```

시험 감각:

```text
특정 AWS 장애가 내 계정 리소스에 영향을 주는지 확인
예정된 유지보수, 리소스 retirement 이벤트 확인
계정별 health event를 EventBridge로 받아 자동화
→ AWS Health Dashboard
```

# 비교 암기

```text
지표와 알람
→ CloudWatch Metric / Alarm

로그 저장과 검색
→ CloudWatch Logs / Logs Insights

로그 패턴을 metric으로 변환
→ Metric Filter

로그를 실시간으로 다른 서비스에 전달
→ Subscription Filter

이벤트 기반 자동화
→ EventBridge

분산 추적
→ X-Ray

AWS 장애/계정 영향 이벤트
→ AWS Health Dashboard
```
